# 謄本線上驗收

> 最後更新 2026-10-14 ／ 對應版本 `b48fa74`（線上同版）
> 現況、決策與待辦另見 [`docs/planning/transcript-status.md`](../planning/transcript-status.md)。

謄本功能的驗收分兩條線，**兩條都要過**：

| 線 | 驗什麼 | 在哪裡跑 |
|---|---|---|
| 抽取邏輯 | 給定一段文字，欄位抽得對不對、全文有沒有讀完 | 本機 `backend/tests/unit/test_transcript_*.py`、`test_section_required.py`、`test_transcript_full_parser.py` |
| OCR 品質與速度 | 一張圖實際讀得出什麼、要多久 | **只能線上**——本機測試環境不裝 OCR 引擎，速度也只有線上數字才有意義 |

本機 unit 綠燈只證明前者。圖片、掃描件的結果一定要送線上看。
**實際要處理的謄本是電子檔**（業主 2026-10-14）；掃描／拍照件的 OCR 品質與速度排到提升機器規格之後。

## 2. 怎麼跑

```bash
cd backend
python scripts/transcript_online_acceptance.py --base http://54.248.201.66:8085 --out /tmp/acceptance
```

- 一律 `enable_llm=false`：不產生費用，量到的是規則抽取本身。
- 與基準不同時，**逐欄對照 `truth.json`** 判斷是改善還是退步；確認是改善再加 `--update-expected` 更新基準。
- ⚠️ **每跑一輪，線上複核佇列約多 7 筆**（圖片都會被判定需要複核，API 目前沒有略過選項）。跑完記下印出的 review id。
- **全文解析（`transcripts`）的「都讀出來」檢查**：`test_transcript_full_parser.py` 的 `audit()`——
  逐行帳目（每一行原文都有去處）、字元對帳（含標點、星號，0 少 0 多）、詞邊界（不黏出原文沒有的詞）。
  三組正對照（黏連、刪遮罩、刪一行）必須被抓到。電子謄本新樣本請先用它跑一次。
- 線上一次只送一份；**不要連送多頁掃描件**（2026-10-13 曾因此 OOM）。

### 3.2 掃描／拍照件（範本 01–07，OCR）
以 2026-10-14 線上版本重放已存的 OCR 原文、逐欄對照 `truth.json`：讀錯或缺的欄位**都是 OCR 把字讀壞或讀漏**，例如：
遮罩星號被吃掉（所有權人 `皮**` 讀成 `皮`）、日期少數字（`民國084年02月日`）、「土」讀成「上」、「層」讀成「唇」、整行沒讀到（02 的總面積）。
OCR 速度：每頁約 15–24 秒（2026-09-21 量測，線上機 1 顆實體核心）。
全文解析在 OCR 文字上**讀不出結構**（OCR 不保留縮排），掃描件請以 25 欄為準。

## 4. 已知限制
- **車位**：公設車位那一行「含停車位○號,權利範圍:…」在 `transcripts` 整行保留為文字、未拆欄位；獨立產權車位未驗（無樣本）。
- **掃描件**：OCR 讀錯字會以信心度 0.9 送出、不進複核；AI 補值（`enable_llm=true`）信心度 0.8 等於門檻、也不進複核。
- **全文解析**：只依「編號」分張（不同地段同編號相連會併成一張）；尾端遮罩接數字（如 `A12345****`）會被當補位去掉；
  對帳證明不漏字不多字，**不證明值掛在正確的標籤**（靠逐項抽查）。以上 5 份樣本皆無此情形。
- **25 欄**：多棟謄本的單值欄位只放第一棟（完整資料在清單欄位與 `transcripts`）；建物謄本的 `area` 是總面積或層次面積的重複值。
- **2026-10-01（`fb3eb1e`）列出、之後未重驗的兩種版面**（範本都沒有）：
  1. 車位編號那一行之後，「權利範圍:」的值折到下一行時，被當成公設持分。
  2. 說明文字「權利範圍:全部時…」的「全部」被當成持分。
  （`581afe4` 改為持分通用讀值後是否仍會發生，未驗。）
- **樓層只在「各層加總 = 總面積」驗證通過時才輸出**；對不上或沒讀到總面積，整頁不給（`floor_area_checks` 會說明原因）。
- 公設的「主要用途」不輸出：只能照抄 OCR 文字（「樓梯間」會被讀成「樓梯問」）。
- 線上複核佇列的舊項目不會隨改版重判。
