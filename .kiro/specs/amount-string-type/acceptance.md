## 規則（業主原話 → 可檢查條件）

| ID | 可檢查條件 | 原話（2026-10-29） | 讀法註記 |
|---|---|---|---|
| R1 | 帳單、合約、謄本的欄位值由模型補值（非直讀的 LLM 補欄位）時，若模型回數字（JSON number），寫進 `pages[].structured_data` 與 `document_fields` 的是字串；不再出現數字型別的欄位值 | 業主「處理」，回覆的是主持人建議原文：「把金額統一成字串……根本的修法是讓程式一律回字串」 | **放寬**：建議原文說「金額」，本規則涵蓋同一入口的所有欄位（帳單 `account_no`、謄本 `area`、`total_floors` 等也會被模型回成數字，基準探針實測到）。依據業主既有裁定「通用處理，不打局部補丁」（專案記憶 general-fix-not-local-patch）：只轉金額欄位得另列欄位清單，是局部補丁 |
| R2 | 轉換格式：整數值回不帶小數點的數字字串（`714` → `"714"`、`25000.0` → `"25000"`）；非整數回 Python `repr` 形式（`1234.5` → `"1234.5"`、`45.67` → `"45.67"`）；`true`／`false`、物件、陣列不轉 | 主持人補（為了讓 R1 可檢查） | 不加千分位、不補幣別：模型回的就是不含格式的數字，字串化不另外猜原文格式 |
| R3 | 其他行為不變：規則抽取與直讀的值（本來就是字串）不變；哪些值會被採用（帳單、謄本：值為真才採用；合約：非 `None`、非 `""` 才採用）、信心度、`needs_confirmation`、`validation_warnings`、是否進複核都與改前相同 | 隱含於「統一成字串」（只改型別） | 主持人補 |
| R4 | 規格文件與程式同步：`docs/api/INTEGRATION.md` 刪去 2.7.1 的「金額可能是數字」說法（其中「非直讀路徑（文字層 PDF 等）」本身也與程式不符：文字層不呼叫模型），改寫為一律字串；版本升 2.8.0 | 業主 2026-10-28 定案「規格文件 和實際程式 都調整」，本片沿用 | — |
| R5 | 線上部署後，線上回應符合 R1 | 「處理」包含上線；部署授權列在核可題 | 部署與回退要業主授權 |

## 判分

- 「數字型別」＝ Python `int` 或 `float`，且不是 `bool`；檢查巢狀 dict，跳過 `field_confidences`、`extraction_confidence`、`confidence`（這些本來就是數字）。
